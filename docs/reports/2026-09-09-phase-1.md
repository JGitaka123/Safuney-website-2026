## Risks I see that you didn't ask about
- Money is `BigInt` everywhere (ADR 0004). Anyone adding a money column as `Int` or `Float` will be
  caught in review, but there is no lint rule yet; that lands with the payments package in Phase 3.
- The append-only order-event trigger has one deliberate escape hatch for hard deletes inside a
  transaction (migration `20260909070000`). It exists for test cleanup and signed-off erasure requests
  only; the admin UI will never expose it.
- Vercel preview protection is on by default and will block the preview smoke tests until runbook §7 is done.
