# Phase 3 — Cart and checkout

**Date:** 2026-09-09 · **Branch:** `claude/funny-thompson-2lukly` → PR to `main`

## What shipped
- `packages/payments`: provider abstraction with Daraja (STK push, status query, C2B parse), Paystack,
  invoice and cash-on-delivery adapters, a mock mode for previews/CI, and 16 unit tests (initiation,
  whole-shilling rounding, secret path + source IP + signature verification, tamper, replay keys,
  timeouts, status mapping). ADR 0006.
- Order service: totals recomputed from the catalogue in a transaction, stock reserved with row locks
  and CHECK constraints, order numbers `SFN-YYYYMMDD-NNNN`, append-only events, payment initiation with
  an attempt cap, idempotent callback handling with amount verification, status polling with provider
  reconciliation, reservation expiry (cron). 9 integration tests including oversell, forged and tampered
  callbacks, replay, cancellation + retry, COD, invoice refusal for guests, delivery-zone refusal.
- Delivery fee engine: zone × weight × order value rules with a free-delivery threshold; pickup free.
- Checkout page (contact → delivery → payment → review, progressive disclosure, keyboard-complete),
  M-Pesa pending page with countdown, resend and "choose another way", card return page, confirmation
  page, guest order tracking page with an event timeline. Explicit, recoverable failure states.
- Order confirmation email (Resend) and SMS (Africa's Talking) when configured; "payment received"
  notification after a verified callback.
- Money type guard in CI (`pnpm guard:money`).

validation and keyboard-only flows; Lighthouse on `/cart` and `/checkout`.

## Risks I see that you didn't ask about
- Daraja callbacks are unsigned; the secret path + IP allowlist + amount match is the strongest check
  available. Keep `MPESA_CALLBACK_SECRET` long and rotate it if it ever appears in a log.
- Stock reserved by unpaid M-Pesa orders is held for 30 minutes; a rush of abandoned checkouts could
  make a pack look sold out. The cron releases it; the window is a setting we can shorten.
