## Flags, and what "off" means
`/admin/flags` (ADMIN only, through the Phase 6 audited seam, so switching a feature on is a recorded
act with a name against it). Every flag defaults to **off**, and off means the feature is
**unreachable** — the route returns 404, not merely a missing link. A hidden link is not access
control, and e2e asserts the refusal for every flagged route.

## The advisor, and why it is built the way it is
A customer describes a cleaning problem; we answer with products we actually sell. The catalogue is
searched **first**, the model is given only what came back, and anything it names that was not
retrieved is **dropped after the fact**. Prompting alone reduces hallucination; it does not make it
impossible, so the constraint lives in code where it is a `Map.get` that either finds the slug or does
not (ADR 0013).

The model never sees a price. The server is the price authority, and a model that has seen a price can
quote one. A test asserts no price appears in the request body.

Nine tests fix the behaviour: an invented product is dropped and logged as a lead; a mixed reply keeps
only the real product; a failed model call is admitted rather than papered over; a fenced JSON block is
tolerated; and a question with no catalogue match never reaches the model at all — it becomes a lead,
which is the most commercially useful thing the advisor produces.

## The planner, and two bugs its tests caught
Facility type and size in; monthly consumption, colour-coded kit and a printable schedule out. Writing
the tests found two real errors in my own arithmetic:

1. **Products used neat were halved.** Hand gel, laundry dosing and enzyme drain treatment carry ratio
   1, and running them through the `(ratio + 1)` concentrate maths ordered half of what a site needs —
   for a 50-bed ward, the difference between enough hand gel and running out in week three.
2. **The total did not equal the column above it.** It was summed from unrounded figures while the rows
   were rounded. The first person to add up the table would have stopped trusting the whole plan.

Both are fixed, and both now have a test that would catch them again.

## What else shipped
- **Compliance hub**: SDS and COA with full version history (the chain is walked, bounded), and an
  organisation-level "tell me when this changes" subscription. Which organisation is decided by the
  caller's membership, never by a value the form sends — the same rule as quote acceptance in Phase 4.
- **PWA**: installable, with a service worker that caches the shell and static assets and **never**
  anything priced, personalised or transactional (ADR 0014). Any request carrying a cookie is excluded
  regardless of path, because path lists rot. Turning the flag off **unregisters** the worker and clears
  its caches — a service worker outlives the page that installed it, and without that the flag would
  stop being a flag.
- **Live stock and ETA**: availability is on-hand minus reserved, and an exact count is shown only when
  it is low. "3 left" is useful; "417 in stock" tells a buyer nothing and hands a competitor a stock
  figure.
- **Loyalty**: volume tiers surfaced to the customer (the pricing engine already picked them; a buyer
  who cannot see that ten is cheaper than eight does not order ten), and an annual spend statement that
  counts only paid or fulfilled orders so it reconciles against the customer's own ledger.
- **Sales-rep mode**: visit notes with optional GPS. Location is a deliberate tap, never automatic — a
  prompt on page load trains people to dismiss it — and a fix worse than 500 m is dropped rather than
  stored, because a coordinate that could be any of four buildings is not evidence of a visit. New
  `RepVisit` model with a database CHECK that latitude and longitude are both present or both absent.

## Verified (local production build)
- 136 unit and integration tests in `apps/web` (22 new), 24 in the packages.
- 175 Playwright + axe tests, mobile first and desktop, 174 green and 1 skipped.
- Lint, typecheck, build, placeholder guard, money guard and Swahili guard clean.

**One test-infrastructure fix worth naming.** Staff sign-in is rate limited to five attempts per address
per ten minutes. As specs multiplied, several started signing in as the same demo accounts and the suite
began failing for a reason that had nothing to do with the code under test. The wrong fix is to relax the
limit. The right one is a Playwright setup project that signs each role in once per run and shares the
state — four sign-ins per run, however many specs there are.

## PO actions needed
1. **Nothing here is visible to customers yet.** Go to `/admin/flags` and switch on what you want, one at
   a time, after you have seen each one work. The features are ordered there as the brief ordered them.
2. **`ANTHROPIC_API_KEY`** in Vercel if you want the advisor. Without it the page still takes the
   customer's description and routes it to your team; it does not pretend to answer.
3. **Check the planner's numbers against a site you know well** before switching it on. They are derived
   from coverage at stated dilutions and standard frequencies, not from your own consumption data — and
   the page says so, but you are the one who can tell whether they are close.

## Risks I see that you didn't ask about
- **The advisor costs money per question.** It is a server action, not a public API, and rate limited per
  IP — but a busy day is a real bill. Watch it for the first week.
- **Answer quality is bounded by search quality.** If retrieval misses a product, no prompt recovers it.
  That is the honest argument for the semantic search this phase deferred.
- **The annual statement will be checked against your accounts.** It counts paid and fulfilled orders and
  excludes cancelled and refunded ones. If your finance team defines a year differently — say, by invoice
  date rather than order date — tell me and I will change it before anyone reconciles against it.
- **Visit GPS is personal data about your staff**, not just about the customer. It is optional, consented
  per visit, and coarse — but it is a record of where an employee was, and Kenya's DPA applies to it.
  Tell your reps it exists.
